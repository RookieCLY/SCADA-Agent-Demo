## 5. 关键设计取舍记录

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| Phase 1 不引入 LangGraph | 用原生 Python `while` 循环代替 | LangGraph 锁版本是 Phase 2 任务;Phase 1 主目标是验证 World / Tool / Dispatcher / 状态机契约,在原生循环里反而更易调试 |
| 每个 action 单独是一个 `MockTool` 子类 | 而非"一个 Domain Tool 一个文件" | 让 `intended_entities` / `referenced_entities` 元数据声明天然落到调用单元上,Cascade Failure 检测的前置硬约束(§G.3)无需额外接线 |
| `MockLLM` 用正则脚本而非 stub-fixture | 单文件 + 状态键 dict | 让 Phase 1 验收脚本(`README` 的 quick-start)与单测共享同一 fall-through 行为,且未来真实 LLM 接进来时 `LLMProvider` 协议一行替换 |
| `Tracer` 的 Langfuse 接入做成条件初始化 | 仅当两枚环境变量都在时才尝试 import | 满足"不设置 API Key 也能完成 Phase 1"的硬约束;Langfuse 包未装时不报错 |
| 反查表完备性自检放在 `build_default_registry()` 末尾 | 而非测试断言 | 任何后续新增 Tool 一旦漏接 `(domain, action)` 反查项,启动期就 fail,而不是实验中段才发现指标分母异常 |
| Mock Tool 的 `world_diff` 直接由 Tool 返回 | 而非由 Tracer 反推 | Tool 自己最清楚自己改了什么,反推等价于复述一遍逻辑,易漂移;由 Tool 返回后 Tracer 只做记录 |
| 终态匹配 `subset` 为默认模式 | 而非 `strict` | 多步任务允许 Agent 添加合理辅助配置;Golden Dataset 通过 `match_mode` 字段单条覆写为 `strict`(负例)或 `key_fields`(实现细节宽松) |

## 8. 结语

Phase 1 完成的不是"一个能跑的 Agent",而是**一组可被实验度量的契约**:

- World 是事实基线,Tool 是 World 的合法写入路径,Tracer 是这条路径上每一步的可观测记录,状态机+白名单是物理上能不能写的门禁
- 这四者的契约在 Phase 1 已经被 71 个单测钉死;Phase 2 接入 RAG / Workflow / 真实 LLM 时,只要不破坏这些契约,后续指标(F1 / 越权调用率 / 终态匹配率 / Cascade Failure Rate)就能一致地计算出来
- "不设 API Key 也能完成 Phase 1"得以实现的关键不是某个巧妙的技巧,而是把 LLM 抽象成 `LLMProvider` 协议、把 Langfuse 做成可选副作用——这两个边界一旦立住,后续从 mock 切到真实模型就是一行配置
